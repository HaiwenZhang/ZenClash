# ADR 0001：集中运行时变更并拆分高杠杆模块

状态：已接受

ZenClash 需要同时协调托管或外部内核、有效配置、系统代理、代理选择和实时流量。此前这些规则散落在首页、代理页、托盘、悬浮窗和启动退出路径中，同一行为存在多套实现，失败时难以判断运行事实。参考 `examples/clash-verge-rev` 的生命周期锁、配置事务和集中采样思路后，本项目采用适合 GPUI 与现有 Tokio 运行时的 Rust 实现，不复制 Tauri、React 或平台特定宿主结构。

核心选择是提供意图驱动的 `CoreSession`，通过 `open`、`apply`、`maintain` 和 `shutdown` 表达运行时变更，并在内部用异步互斥和代次串行化生命周期。有效配置先生成和校验，再应用；只有应用成功才提交本地状态。明确的配置拒绝不盲目重启，只有托管内核遇到能力缺失、传输中断或结果不确定时才允许受控重启；外部内核永不由 ZenClash 重启。

系统代理、代理操作和逻辑流量采样保留为独立深模块。系统代理分别记录持久意图、操作系统实际状态和可验证所有权，并以事务完成启用、恢复和退出释放。代理操作统一处理“切换成功但清理连接失败”的降级结果、内核回读和提供者感知测速。实时流量只产生一份有序、定长的逻辑采样，首页、悬浮窗和 macOS 状态栏共同消费，页面调度不再拥有采样历史。

代价是需要迁移现有调用方并增加结构化结果类型，但可删除重复的重启、代理切换、测速和采样逻辑。所有迁移以行为测试固定现有可见行为；仅修复测试证明的缺陷，平台失败路径保持可恢复，退出清理失败仍采用尽力而为并允许应用退出。
