# ZenClash 与 clash-party / FlClash 功能对照

本表同时审计 `examples/clash-party` 的 renderer、preload IPC、main service，以及
`examples/FlClash` 的桌面页面、Bloc/Service 与独立 core 进程。移动端 VPN、Android
应用路由等平台专属能力不属于 ZenClash 桌面客户端范围。不把“存在同名页面”视为
已实现；只有能够追到真实内核 API、操作系统调用、文件持久化或后台服务，并具备
错误处理与状态回读的功能才标记为“已实现”。

状态说明：

- **已实现**：有真实副作用和状态回读。
- **部分实现**：核心路径可用，但缺少参考实现中的高级选项或持久化。
- **缺失**：尚无可用后端；仅有静态 UI 时也按缺失处理。
- **延后**：有参考实现，但不是代理客户端的必要闭环，当前明确不扩张范围。

## 范围裁剪结论

两份参考项目共同具备、且桌面代理客户端不可缺少的闭环为：内核生命周期、Profile
与订阅、代理选择与测速、连接、流量、日志、系统代理、TUN、规则/Provider、托盘、
备份和网络诊断。ZenClash 已为这些能力连接真实后端。当前新增的必要能力只有双内核：
Mihomo 作为默认完整内核，meow-rs 作为显式实验选择；不会因下载失败静默改变内核。

以下功能不作为当前开发目标：clash-party Smart Core、插件市场、主题仓库、age/Gist、
SSID 自动策略，以及 FlClash 的 Android/VPN 专属功能。全局快捷键、应用内自动更新、
悬浮窗位置持久化属于可用性增强，等核心稳定和安装包签名链完整后再评估。

| GeoData / 外部 UI 升级 | 部分实现 | Mihomo 可调用 `/configs/geo` 与 `/upgrade/ui`；meow-rs 明确禁用不支持的接口并显示原因。两种内核都能通过完整配置事务保存资源设置 | URL/间隔编辑器、独立下载哈希校验和资源回滚 |
| Smart Core / AI 最优节点 | 延后 | 无 Smart group 权重或缓存 API | clash-party 特有扩展，不属于当前必要闭环 |

### meow-rs 能力边界

meow-rs 复用代理组/节点、Provider、模式、TCP 连接、流量、日志、版本和常用配置读取 API。
其当前 API 不承诺完整 Profile 热重载、单条规则启停、Mihomo 原生升级、GeoData 更新、
External UI 更新、MRS 转换或完整 UDP 连接追踪，因此 UI 通过静态能力表禁用这些入口并
给出原因。真实集成测试会启动本地 meow-rs，读取 controller 数据，并执行一次配置写入、
进程重启和运行模式回读，再通过真实 Mixed 监听转发本机 HTTP 请求；这不是 mock 测试。

| IP 信息与网络探测 | 已实现 | 保留本机接口/网关/DNS 信息，并支持 IP.SB、ipwho.is、ipapi.is 三种真实公网 IP/地区/ASN/代理识别数据源；Google、Cloudflare、GitHub 与最多 13 个自定义 HTTP(S) 目标并行测速，逐目标隔离错误；可在直连和当前 Mihomo HTTP/Mixed 监听间切换，数据源、路径与自定义目标原子持久化；请求限制超时、重定向和响应大小，真实 Mihomo 回归验证请求确实经过内核代理端口 | 卡片拖拽顺序属于展示偏好增强 |

## 后续实施边界

1. 先稳定双内核的真实启动、配置事务和共同 controller API，不扩展第三内核。
2. 只补影响可靠性的缺口：平台权限恢复、安装包携带/定位内核、失败回滚和真实集成测试。
3. 可用性增强按小批次评估：悬浮窗位置、全局快捷键、应用更新，不与核心功能混做。
4. Smart Core、插件/主题市场、JS 覆写、age/Gist、流量配额等维持延后或不开发。

每批功能必须同时包含：核心服务 API、GPUI 事件处理、错误呈现、状态回读、单元测试，
以及在能力允许时使用真实 Mihomo、真实 meow-rs 与真实 YAML 的集成回归。

`ZenClash` 的运行时设置写入必须使用写后回读验证。真实 Mihomo 回归已确认：
`PATCH /configs` 会对某些不支持的字段返回成功但静默忽略（例如完整 sniffer 对象）；
因此 HTTP 2xx 本身不能作为“功能已实现”的证据。这类配置现在走独立 controlled-config
覆写：源订阅不变，完整 effective YAML 先由真实 Mihomo 接受，再原子持久化；提交失败会恢复上一运行配置。
meow-rs 的完整配置写入不走这条不完整 API，而是通过可回滚的托管进程重启验收。
