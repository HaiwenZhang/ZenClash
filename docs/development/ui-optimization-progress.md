### SSID 后台轮询补充优化

- 非 macOS 平台在创建任务前返回，不再每秒唤醒并复制不受支持的 Wi-Fi 规则。

- 本次 macOS 验证：控制器模块 8 项测试通过，UI crate 全目标全功能严格 Clippy、格式和差异空白检查通过。测试覆盖切换策略，不覆盖真实 Wi-Fi 断连/重连；跨平台运行及实际节能收益未测量，不作为原始长卡顿已解决的证据。

### 实施约束

- 不新增依赖，不改变持久化格式，不拆分 crate。
- 普通偏好更新仅合并该功能负责的字段，完整备份恢复仍具有全量覆盖语义。

## 按冲突范围管理修改操作

- `RuntimePage` 不再持有全局 `mutating` 布尔值。内核/配置、日志偏好、语言、流量历史、网络诊断偏好及备份分别声明操作域。同域串行，备份与全部修改域双向互斥；日志复制/导出继续由各自视图状态管理。
- 每次修改获得独立代次令牌；完成和早退路径按令牌释放。重复完成不能释放同域后续操作，日志偏好完成不能清除内核操作状态。规则集导出原先丢弃开始令牌的路径也已改为保留和释放实际修改令牌。
- 普通偏好保存不取消控制器页面读取，也不暂停其周期刷新。内核/配置及备份仍使旧读取失效。流量历史清理与其偏好保存共享同域，避免设置与清理交错。
- 语言和偏好按钮、日志持久化/流量历史/网络路由开关、备份按钮使用对应域的禁用状态；开关复用现有组件及样式。
- 三项冲突模型测试覆盖独立偏好与内核并行、所有域与备份的双向互斥、重复完成不释放新任务。`fmt`、全目标全功能编译及 `clippy -D warnings` 通过。全工作区串行回归 `cargo test --workspace --all-features --locked --offline -- --test-threads=1`：529 项通过，6 项忽略。首次默认并行回归在既有 `changed_mixed_port_checks_udp_occupancy` 断言失败；该测试随后单独运行和全量串行均通过。同号 TCP 端口竞争是代码可见的可能原因，首次错误文本未被原断言输出，故不宣称已证实或修复这一间歇失败。
- 完整应用交互仍待验收：慢速偏好保存期间切换页面执行内核配置；备份执行期间尝试各类保存；失败后重试；切页后任务完成再返回原页。预期互斥范围与模型一致、成功数据收敛、控件状态恢复。真实内核生命周期和 Windows 不以这些模型测试替代。
