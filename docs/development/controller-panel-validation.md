# 控制器、SSID 与菜单栏面板验收

## 实现边界

- `zenclash-core/src/controllers.rs` 拥有版本化存储、输入校验和 SSID 去抖规则；UI 的 `app/controllers` 拥有目标选择、编辑表单和远程会话。
- 切换的提交顺序为版本探测、运行配置探测、原子保存、替换页面。探测失败或保存失败不替换当前会话。旧会话释放后流量及日志监控随之停止；本机托管生命周期不随远程选择改变。
- 远程仅允许代理组、连接、日志和规则。`RuntimePage` 的远程构造不加载本地持久化配置，不提供日志持久化开关，并限制导航范围。
- 菜单栏及悬浮窗始终显示、控制本机，面板明确显示「本机控制器」。主窗口远程视图显示控制器名称。
- macOS 权限通过 `CLLocationManager` 显式请求，不启动定位更新。`CWEventDelegate` 对应的 SSID/链路回调只更新原子版本，后台读取关联 SSID；30 秒兜底处理遗漏事件。关闭规则或退出时移除委托并取消事件注册。
- 存储是新增独立文件，旧版可忽略，现有配置备份暂不包含这两个文件；密钥不是加密存储。原子写入在 Unix 上从创建临时文件起就使用 `0600`，Windows 沿用应用数据目录的 ACL。

## 自动验证

```sh
cargo fmt --all -- --check
cargo check --workspace --all-targets --all-features --locked --offline
cargo test --workspace --all-features --locked --offline
cargo clippy --workspace --all-targets --all-features --locked --offline -- -D warnings
```

网络单元测试绑定本机临时端口，必须在允许监听本机端口的环境运行。测试覆盖探测失败保留记录、成功探测提交顺序、密钥脱敏及 Unix 文件权限、损坏数据保留、SSID 去抖和手动选择保留、远程导航边界、面板边界翻转与小屏适配。它们不替代系统权限或真实窗口交互验证。

## 原生手工验证（尚待验收）

使用独立测试账户和两个可丢弃的 Mihomo 控制器；不要使用生产订阅或密钥。macOS 使用当前源码打包的应用，Windows/Linux 只验收控制器和托盘，不提供 SSID 自动切换。

1. 添加 A/B 控制器，检测 A，切换 A→B→本机。确认节点、连接、日志不残留旧目标内容，本机 PID、代理和 TUN 不因切换而改变。
2. 为 B 输入错误密钥或不可达地址。切换失败必须保留 A，重启应用仍恢复上次成功目标；修复后可再次切换。模拟存储目录不可写，确认不能出现页面已切换但记录未保存。
3. 删除当前目标后返回本机；修改目标地址必须重新探测。关闭或切换远程会话后，通过测试控制器的 WebSocket 连接数确认旧采集连接释放。
4. SSID 默认关闭。依次检查未授权、拒绝、系统定位服务关闭、授权后的状态；不允许采集位置。CLI 启动显示应用包要求，不应触发无效授权弹窗。
5. 配置 Wi-Fi A→配置 A、Wi-Fi B→配置 B。切换网络并等待两次稳定观察；快速 A→B→A 最终应选择稳定网络对应的配置；已经发起的配置事务按现有串行流程收尾。无规则网络保持原配置。
6. 自动选择完成后手动选其他配置，同一 Wi-Fi 不反复覆盖。切到远程时暂停规则，返回本机后重新判断。删除规则引用的配置、破坏目标 YAML、停止本机内核，确认可见错误或跳过，保留当前可用状态。
7. macOS/Windows 左键打开面板，右键打开菜单；Linux 从原生菜单的「打开状态面板」进入。测试模式、配置、节点选择及失败反馈；Esc 先关闭节点下拉，再关闭面板，点击外部关闭。测试重复点击、隐藏主窗口后打开、主窗口唤起和应用退出。
8. 多显示器（含左侧负坐标及不同缩放）、底部/侧边任务栏、窄屏、浅色/深色、中英文、Tab/Enter 键盘操作，检查面板边界及控件可达性。
9. 在探测、SSID 读取或配置切换未完成时退出，确认没有重新打开窗口、重新注册监听、重启本机或恢复系统代理。真实网络及系统代理/TUN 恢复另按 [自动运行维护验证](automatic-runtime-validation.md) 执行。
