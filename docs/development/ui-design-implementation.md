# 桌面 UI 设计落地与验收

设计来源为 [UI 设计目录](../ui-design)，包含总览、代理组、订阅、连接、规则、日志和设置的明暗主题稿件。页面使用现有 GPUI Kit 组件、状态所有者和后台投影，不新增依赖或持久化格式。

## 布局约定

- 共享 224 px 主导航、工作台面包屑、页面标题与说明、明暗主题切换入口。导航名称与页面标题区分，例如“总览”对应“网络总览”；中文与英文同步。
- 使用统一背景、卡片、边框、蓝色图表和薄荷色交互强调色。卡片圆角统一为 8 px，页面横向内边距为 24 px，主要卡片间距为 12–16 px。
- 总览将网络接管和当前节点合并为一个面板，与流量图并列；下方保留进程流量、连接分流、节点延迟、当前订阅和最近连接。
- 代理组使用组导航、节点工作区和当前节点详情三栏。排序与可用性过滤位于节点工作区，节点使用三列网格，每页最多 9 个节点；窄卡片内的操作按钮允许换行。“显示隐藏组”在空状态下仍可访问。
- 订阅使用四项指标、双列配置卡片和额度详情。连接和日志使用搜索、过滤、表格与详情面板；页面操作位于标题区。规则使用类型分布、策略占比、列表和详情。
- 设置使用独立分区导航、主要设置与侧栏信息。侧栏包含版本、更新、工具与本地数据状态。外观使用浅色、深色和系统预览按钮；较窄的空间允许换行。
- 长列表沿用已有分页、后台筛选与 generation 校验。表格在较窄的工作区可横向滚动；侧栏详情允许换行到下一行。

## 数据与交互边界

设计稿中的示例节点、流量、连接、额度和运行时间不写入应用。没有观测结果时显示加载、未知或空状态。侧栏状态表示控制器连接情况，不将连接成功当作内核进程生命周期证据。

规则策略占比使用后台已准备的前五项策略命中统计，分母为这些策略已返回的命中总量；文案明确统计口径。无统计时不展示伪造占比，规则启停状态优先使用已有回读确认结果。

设置的本地配置、覆写数量来自已载入目录。流量历史与日志文件状态展示现有偏好设置，不推断磁盘占用或写入成功。日志复制、导出和清理，以及订阅导入、编辑和应用，继续调用原有操作。

系统代理、TUN、托盘、进程生命周期和服务确认流程保持现有业务约束。新的外观入口复用应用的主题动作和偏好保存流程。

连接与日志提供“暂停展示 / 继续展示”。暂停固定当前列表快照，搜索、协议或级别筛选继续作用于该快照；恢复读取最新数据。成功关闭连接或清空日志会解除相应暂停；离开页面或释放展示状态时丢弃暂停快照。日志暂停不停止采集或磁盘写入。

## 实机验收步骤

原生页面夹具已完成上述截图比对；以下步骤用于完整应用、真实配置与平台交互的后续复核，不属于夹具截图的验证范围。

1. 使用 `cargo run -p zenclash-ui --bin zenclash --release --locked` 启动 Windows 应用，分别设置 1280 × 820 和 1536 × 1024 窗口；记录显示缩放比例。
2. 在浅色和深色主题下依次打开七个设计页面，核对背景、边框、字重、主导航与标题层级。检查长英文文案、长配置名称和长规则内容的截断与详情可读性。
3. 在中文和英文界面下检查页头按钮、外观预览和设置分区导航。缩小窗口后确认换行和滚动不会使搜索、过滤、分页及详情操作不可达。
4. 使用 Tab、Shift+Tab、Enter 和 Space 操作主题、协议过滤、暂停展示、隐藏组开关、分页及详情入口；确认暂停后仍可筛选，恢复后显示最新数据，焦点清晰，弹层关闭后回到合理位置。
5. 使用隔离的测试配置覆盖控制器断开、空列表、全部组隐藏、未知延迟、无额度、无命中统计和未启用日志写入；确认界面表达实际状态。
6. 使用已配置的真实内核检查现有刷新、测速、切换节点、订阅应用与日志操作。网络接管按原有平台验收流程检查失败恢复和退出清理。

截图与记录应使用脱敏数据，不包含订阅地址、控制器密钥或用户日志隐私内容。本次样式与布局修改不提供性能改善结论；性能需要独立 release 测量。
