# UI 响应性优化验证

## 本轮行为与边界

- 内核元数据读取不获取子进程生命周期锁；运行状态使用后台发布的 `OperationalStatus`。停止/重启期间的状态允许短暂落后于真实进程。
- 本地配置与覆写目录初始化在后台读取，完成前页面显示加载状态；主题及托盘偏好即时更新 UI，按操作顺序后台保存，正常菜单退出/重启等待保存完成。
- 节点逐项测速共享同一客户端的 16 个并发名额。结果以 50 ms 聚合窗口、每批最多 64 项提交 UI，展示完成数；离开节点页取消目录读取与逐项测速。已提交的节点选择及恢复自动选择命令仍然完成。
- 运行时页面切换、读取失效及页面销毁会取消该页面的读取任务；已开始的阻塞式平台检测不能被 Tokio 强行中断，已提交的修改操作不受页面读取取消影响。
- 日志页按日志 revision 和搜索条件复用快照与倒序筛选索引；日志轮转、清空后重建，离开页面或隐藏窗口后释放缓存。
- 折叠组不构造节点展示列表。连接列表仅在数据快照、筛选条件或排序改变时重建索引，渲染只读取当前页。
- 配置应用的成功与后续页面读取分开处理；后续读取失败不将已成功的应用操作当作失败。切走页面后完成的覆写/TUN 操作仍同步本地配置状态。
- DNS 等表单使用包含源配置、托管修改和启用覆写的有效配置；提交成功后重新加载表单。

本轮不新增依赖、不迁移持久化格式、不改变 crate 边界。自动测试和独立窗口探针不能证明完整应用的间歇性长卡顿已经消失；既往故障记录见 [代理组闲置卡顿排查](proxy-page-responsiveness-investigation.md)。

## 自动验证

在仓库根目录运行：

```sh
cargo fmt --all -- --check
cargo check --workspace --all-targets --all-features --locked
cargo test --workspace --all-features --locked
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
```

回归测试覆盖持有生命周期锁时读取 UI 元数据、无需 Tokio runtime 的批次等待、生产者未结束时发布结果、批次容量及完整性、任务取消、共享测速名额及取消后的名额释放，以及配置字段保留和连接排序。第二轮新增页面读取替换/销毁取消、慢速 HTTP 连接关闭、修改任务不受读取取消影响、日志快照复用及轮转/清空后的索引更新测试。HTTP fixture 仅验证客户端协议/调度，不替代真实内核集成测试。

## 本轮已执行结果

2026-09-11，macOS / ARM64，基线 `f7dc6f2` 加本轮未提交差异：

- 工作区自动测试：515 项通过，6 项忽略（含需要另行启用的真实内核集成测试）。
- 真实 GPUI 独立窗口：20 组、500 节点、立即 HTTP 响应、两次加载；50 ms UI 定时回调最大间隔 60 ms。
- 探针只覆盖代理目录加载和渲染，不测真实内核、测速点击、系统代理或完整应用闲置恢复。60 ms 是定时回调间隔，不是帧耗时或输入延迟；没有同条件优化前基线，不能据此计算性能提升比例。

## 手工验收（待执行）

在 macOS、Windows 分别用同一源码构建测试；记录系统版本、提交及未提交差异、节点/连接规模、每次操作的响应时间。使用专用测试配置，勿把订阅、密钥或用户日志写入仓库。

1. **停止与重启**：启动真实 Mihomo，进行停止和重启，同时切换页面、滚动及打开菜单；UI 应持续响应，进程应最终退出或重新连接。重复应用退出/重启，确认无遗留子进程。设置 `ZENCLASH_MIHOMO_BINARY` 后单独运行真实内核集成测试。
2. **大组测速**：使用 500 个节点且包含慢节点的测试配置，点击整组测速；快结果应先显示，进度逐批增加。测速时切到其他页面再返回，旧任务不覆盖新页面结果。单节点测速与整组测速并存时，整组结束不清除尚未结束的单节点状态。
3. **日志与连接页**：日志页输入筛选条件并翻页，等待日志滚动淘汰后清空；顺序应为最新在前，清空后无残留行。切走再返回应显示最新日志。准备大量连接，反复筛选、排序、翻页和展开详情，再刷新快照；顺序及记录对应正确，不出现旧快照索引。记录主线程耗时和输入延迟，不能只凭平均 CPU 判断。
4. **配置与导航**：源配置设置 `dns.enable: false`，启用改变 DNS 字段的覆写；首次打开和刷新均应显示合并后的值。保存覆写/TUN 后立刻切走，完成后再返回，状态仍应正确。
5. **应用成功、回读失败**：让测试控制器接受配置更新，随后使页面 GET 请求失败；应用状态应退出忙碌，显示读取错误，不回滚已经成功的修改。恢复控制器后刷新验证真实配置。
6. **偏好与启动**：连续切换主题/托盘可见性并正常退出，重新启动后应保留最后选择。模拟较慢的本地配置读取，启动壳层仍应响应，配置加载完成前不展示可提交的默认表单。
7. **闲置恢复**：系统代理开启、TUN 关闭，切到其他应用数分钟再返回节点页；分别采集 macOS 主线程采样、Windows 性能追踪，并关联控制器耗时。记录是否复现，不能用独立窗口结果代替完整应用结论。
